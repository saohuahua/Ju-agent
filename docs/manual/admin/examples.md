# 审批案例：6999 元退货

本章承接[完整业务案例](../business/examples.md)的 SO-2026-0003。前置条件是专用夹具已把商品金额与订单实付同步为 6999 元，客户已提交质量退货，原客户进度为 `awaiting_approval`。普通历史库不保证具备这些条件。

## 同意与后续处理

1. 选择“主管 审批”，进入“待审批事项”。
2. 核对申请金额 6999 元、订单和客户，并通过关联会话检查客户选择的是哪些商品。
3. 点击同意。预期决定被接受，原售后进入待寄回；页面执行记录可查看后续进度。
4. 切回客户，确认原会话出现寄回输入；使用 `MANUAL-RETURN-001` 登记后应等待收货。
5. 专员确认仓库实际收到商品，再调用内部收货接口。客户进度最终为 `succeeded`，成功资金动作只应发生一次。

主管同意的结果是允许后续业务继续，不能在第 3 步向客户宣告资金已到账。审批执行记录中的“调用结束”也不能覆盖业务结果未知。

## 拒绝、过期与重复处理

要演练拒绝，应使用另一轮隔离测试数据，在第 3 步选择拒绝。观察该原单对应拒绝结果，不再继续寄回退款链路。若申请已被他人处理或已过期，刷新原记录核对结果；不能把冲突当作请求完全没到达。

同一申请不应先同意再为了截图改成拒绝。正常、拒绝、过期属于不同样本，分别保留证据；自动演示验证的是同意链路，其他分支由相关评测用例覆盖，未在本轮逐一做网页操作。

## 交给开发人员的信息

提供实际 `runId`、`approvalId`、`returnNo`、当前状态、操作时间和报错文字。不要提供 API Key 或管理口令。维护人员按[接口示例](../devops/examples.md)查询证据，未知资金按[运维排障](../devops/operations.md)处理。
