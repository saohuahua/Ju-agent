# 集中自测解析

对应[44 道题](集中自测.md)。每组给出判断依据与阅读入口，开放题不要求逐字相同，但应包含关键因果关系。

## 第一部分

**01A：B。** 信息完整、规则固定时，表单与确定性流程可能更简单。模型价值来自处理输入不完整和动态取证，并需要实际比较。**01B：** 批准解决授权，接管改变沟通责任，渠道确认说明外部资金事实；批准无法证明到账，接管也不能清除未知。见[01 章](../01-项目全貌/01-售后业务与项目边界.md)。

**02A：B。** 202 表示受理，断线不撤销后台任务。换键可能制造新受理，应查原运行。**02B：** 先检查业务和渠道是否确认，再检查原工具结果、持久事件和客户端游标。已有可信业务终态但投影未完成时只补投影，不能再调用渠道。见[02 章](../01-项目全貌/02-一次退款请求的全景.md)。

**03A：C。** 必须从入口与组合根追踪调用。**03B：** 某些业务映射必须与任务和执行权在同一连接同步提交，现实分层需要服从原子性要求。迁移首先保持身份、授权、条件更新和共同提交语义，不只是换驱动。见[03 章](../01-项目全貌/03-架构与源码阅读地图.md)。

## 第二部分

**04A：B。** 原键已绑定输入，更换参数不能静默覆盖。**04B：** 隐藏按钮只是 UI 控制，角色鉴权决定可执行的动作，资源归属决定可访问哪位客户的数据。服务端需要两者，直接 API 调用也必须受约束。见[04 章](../02-后端必要基础/04-HTTP接口与身份边界.md)。

**05A：B。** 持久恢复需要旧进程内存消失后仍有可信状态。**05B：** 会话表达交互，任务表达执行，退款表达业务，渠道记录外部动作；等待任务结束可以对应尚未付款，把它们共用终态会丢失事实。见[05 章](../02-后端必要基础/05-数据建模与SQLite持久化.md)。

**06A：B。** 两者都可能在插入前读到不存在，唯一约束和事务才能处理竞争。**06B：** 决定与意图一起回滚，否则出现已批准却没有执行依据。网络等待不能纳入同步数据库事务，既延长持锁，也无法与远端形成同一原子提交。见[06 章](../02-后端必要基础/06-事务唯一约束与条件更新.md)。

**07A：A。** 寄回是正常前置等待，不是调用失败。**07B：** 等待任务可以完成其“建立等待”的工作，调查任务完成只产出建议；退款仍需后续授权条件与渠道确认。状态必须说明所属对象。见[07 章](../02-后端必要基础/07-状态机与异步任务.md)。

## 第三部分

**08A：C。** 模型文本不是资金证据。**08B：** 让模型选择查证和补问，领域代码决定资格与金额，持久业务负责已核验动作。完全确定的任务可以不用模型，不应为展示自主性弱化规则。见[08 章](../04-Agent机制/08-Agent与确定性工作流的分工.md)。

**09A：C。** 参数未完成就执行会把损坏协议变成真实动作。**09B：** 调用 ID 关联原动作与结果，多工具、补问和恢复都依赖它。模型轮次确认避免重新产生已确定动作，工具确认说明哪个结果已被宿主保存，未确认结果不能冒充成功。customer-guidance-v1 中 conclude 只结束普通答复的一轮，补齐工具结果后仍为 awaiting_input，客户可继续问；较早版本的 conclude 才按原契约进入 completed。见[09 章](../04-Agent机制/09-原生工具调用与Agent循环.md)。

**10A：B。** 默认持久会话没有直接调用旧压缩管理器。**10B：** 缺订单号会破坏业务归属，缺调用配对会损坏模型协议，删除未决问题会导致错误结束。应保留原事件、证据身份与版本，可按权限回读；业务执行仍需读权威记录。见[10 章](../04-Agent机制/10-多轮澄清与上下文管理.md)。

**11A：B。** 目录约束模型可选能力，不能约束绕过模型的接口请求。**11B：** 文档文字是不可信数据，不是可扩大权限的指令。验证要检查越权读取、未授权动作和副作用是否发生，也检查客户输出，不能仅看是否说了“拒绝”。见[11 章](../04-Agent机制/11-工具门控与安全边界.md)。

**12A：B。** 来源真实仍可能不适用，生成也可能误读。**12B：** 报告所有相关指标，说明 Top3 改善与 Top5 下降并存，保留默认策略是有依据的选择。24 题包含争议和无答案题，主相关性指标分母按协议分别为 tuning、holdout 各 10。见[12 章](../04-Agent机制/12-政策检索引用与确定性判定.md)。

## 第四部分

**13A：B。** 批准只允许进入退货流程，收货等条件仍未满足。**13B：** 消费授权与任务共同提交避免凭据用掉却丢任务，或任务创建但授权仍可复用。已发送、未知的许可不能借收货重新获得，否则可能重复退款。见[13 章](../05-资金执行与恢复/13-从售后申请到审批与执行.md)。

**14A：C。** 超时只说明本地没得到确定结果。**14B：** 恢复进程仅看意图无法区分请求尚未发和已发未确认，因此当前保守阻塞。没有渠道幂等和查询时，本地锁无法消除网络空窗，需要新协议或人工与补偿方案并说明风险。见[14 章](../05-资金执行与恢复/14-退款幂等与结果未知.md)。

**15A：B。** 代次决定当前写入资格，旧响应不能凭到达顺序写回。**15B：** 租约限制 Worker 资格，调用超时限制单次等待，任务期限限制整个推进。三者都不能单独证明外部未执行，仍需资金协议。见[15 章](../05-资金执行与恢复/15-Worker租约与检查点.md)。

**16A：B。** 已完成业务只需恢复展示关联。**16B：** 应确认旧进程退出、新进程从同一持久库恢复、故障点到达、原键和计数不变。取消可以发生在外部已成功之后，停止后续计算不等于撤销资金。见[16 章](../05-资金执行与恢复/16-跨进程恢复与人工核验.md)。

## 第五部分

**17A：B。** 客户投影保留原序号，内部事件被隐藏后可以跳号。**17B：** 业务终态不代表传输尾部追平，应等待完成帧。离开再返回同一 runId 是新一次页面选择，旧请求结果仍可能过时，选择版本用于识别这一点。见[17 章](../06-交互与运行治理/17-SSE事件投影与前端状态.md)。

**18A：C。** 供应商可能已经处理，缺用量不能推出免费。**18B：** 模型尝试是供应商调用，Worker attempt 是任务认领，渠道 submissions 是资金提交；恢复可能增加认领和查询而不增加资金提交。把它们混算会误判重复动作。见[18 章](../06-交互与运行治理/18-模型预算与费用账本.md)。

**19A：B。** 人为等待和模拟输出不能证明真实质量与费用收益。**19B：** 输入版本不变且已确认的分支可复用；失败分支和汇总需明确缺失与保守建议。运行记忆是本次冻结投影，不持续刷新资金状态，也没有跨会话偏好管理。见[19 章](../06-交互与运行治理/19-有限双分支调查与运行记忆.md)。

## 第六部分

**20A：B。** 两种检查对象不同，定向用例还可能被全仓测试包含。**20B：** 结构校验只说明 Judge 协议合法，真实判断需人工标注校准。零样本指标为 1 是计算默认值，不提供质量证据；至少一次成功不等于每次可靠。见[20 章](../07-验证与设计取舍/20-测试L1L2与Judge.md)。

**21A：B。** 单库备份一致不等于双库联合时点一致，哈希只核验文件内容完整。**21B：** 新演示创建新的业务事实，重启继续原库，备份恢复是在新位置复用备份事实；镜像、Linux 原生模块、卷权限、信号和容器浏览器行为仍需目标环境检查。见[21 章](../07-验证与设计取舍/21-本地演示双库备份与恢复.md)。

**22A：C。** 面试主题不是已实现证据。**22B 参考**：SQLite 的候选替代是服务型数据库，触发条件可为多节点共享与写入瓶颈。必须保留业务唯一约束、授权与命令共同提交、围栏写回及原资金键。新增验证应包括两个真实连接或进程竞争、事务回滚、故障恢复及渠道计数，而不只跑 DDL。见[22 章](../07-验证与设计取舍/22-设计取舍局限与迁移条件.md)。

开放题回答只列名词仍不充分。例如“加锁、加幂等、加重试”没有解释锁保护哪项事实、键标识什么、未知为何不能重发。能够指出失败窗口和应保留的记录，才达到本教材的实现理解目标。
