# 业务流程练习

这些练习检查能否根据具体事实推导业务行为，而不是复述术语。题目中的金额和时间为教学构造，除明确引用外不是运行记录。先写判断、理由、记录变化和下一位处理者，再查看[独立解析](业务流程练习解析.md)。

建议每题用一张状态表或一段流程图作答。引用源码时说明它证明哪项判断，不需要复制整段函数。原技术练习保留在[渐进重建练习](渐进重建练习.md)。

<a id="b01"></a>
## B01 判断能力和入口

**B01A**：业务 Worker 的工具列表包含补偿和价保，客户会话受理只接受两种退款动作。产品同学因此说“客户已经可以通过聊天领取补偿”。这个结论是否成立？列出至少三个还必须核实的环节。

**B01B**：客户没有订单号，只说“昨天买的耳机坏了”。系统查询出两张本人订单，其中一张含两个商品。请写出提交申请前的必要过程，以及客户、Agent、领域服务各负责什么。

<a id="b02"></a>
## B02 对象与状态组合

**B02A**：退货的等待任务 completed，售后 awaiting_buyer_shipment，退款 created。数据是否矛盾？请说明三个对象各自的职责，并画出后续两次角色交接。

**B02B**：退款表没有 unknown 状态，但页面显示待核验。你会查哪些事实？如果通用状态表允许 failed 转 executing，是否意味着现在能重发退款？

<a id="b03"></a>
## B03 资格与金额

**B03A**：订单属于客户，没有已有售后，已支付且未发货。金额分别为 4999.99 元、5000 元时，未发货仅退款的最终结果是什么？质量问题仅退款 20 元，签收 3 天，又是什么结果？

**B03B**：无理由退货的签收时间为 9 月 1 日 10:00。申请时刻分别为 9 月 8 日 10:00 与多一毫秒，资格如何变化？再假设订单包含普通商品和生鲜，但只选择普通商品，当前实现会如何判断？

**B03C**：A 商品单价 120 元、数量 2，B 商品 80 元、数量 1，订单总额 320 元。整单与仅选 A 的金额分别是多少？能否通过只传 A 的 itemId 退其中一件？首次部分退款完成后，是否能推断剩余商品可再次申请？

**B03D**：政策拒绝与越权访问都会导致不付款。两者应生成什么不同的业务结果？如果传入不属于订单的 itemId，售后金额函数与价保服务是否有相同的验证行为？

<a id="b04"></a>
## B04 仅退款闭环

**B04A**：从“我要退款”起，手绘受理、补问、建单、自动授权、资金执行、客户反馈的流程。每步标明可信输入、关键持久记录和响应意味着什么。

**B04B**：客户端未收到创建请求的响应；另一个场景是渠道付款响应丢失。两种重试是否相同？分别说明请求键、业务键和查询原结果的作用。

<a id="b05"></a>
## B05 退货后退款

**B05A**：审批刚通过，客户还没寄回。主管直接调用收货接口应否成功？请补齐从批准到退款之间不可省略的步骤，以及每个步骤在证明什么。

**B05B**：客户登记寄回后网络中断，重复提交；人工接管后，又通过同一消息接口携带结构化运单。分别分析当前行为，不能只回答“幂等处理”。

<a id="b06"></a>
## B06 审批交接

**B06A**：两位主管同时批准和拒绝同一 pending 审批。服务器如何决定哪一个有效？若决定已提交但进程立刻退出，什么记录让后续工作不会丢失？

**B06B**：审批时限已过，执行权显示 unknown。能否通过过期处理释放许可并重新申请？自动批准路径是否也必须创建人工审批令牌？

<a id="b07"></a>
## B07 人工与结案

**B07A**：当前 handling_human 案件关联审批 approved、任务 completed、退款 executing。能否结案？预览无阻塞之后新增一笔未执行补偿，提交结案时应如何处理？

**B07B**：正在退款的来源运行 A 请求人工，系统另开人工运行 B，只通过 human.requested.sourceRunId 关联 A。B 后续结案是否证明 A 退款成功？当前仓储会自动跨该关联核验吗？

<a id="b08"></a>
## B08 其他业务

**B08A**：50 元与 50.01 元补偿分别如何分级？同订单同原因已有 failed 补偿，能否再建新单？

**B08B**：签收 3 天，无进行中售后。A 成交 100 元、当前 80 元、数量 2；B 成交 60 元、当前 70 元、数量 1。整单价保多少？只选 B 呢？若已有 failed 售后或无法查询 A 当前价，又有什么变化？

**B08C**：换货在收货后 completed，可以写进项目介绍为“完成库存扣减与补发物流闭环”吗？请给出实现支持的准确表述。

<a id="b09"></a>
## B09 物流与评价

**B09A**：给持久客户会话注入 lost 物流事件会走什么入口限制？物流状态为 delivered，是否能推断订单 deliveredAt 已更新？

**B09B**：客户在 handling_human 时提交五星。评价是否合法，是否推进退款成功或会话 completed？看板 customer 来源的完成率是否等于真实客户自动退款成功率？

<a id="b10"></a>
## B10 页面与综合重建

**B10A**：模型消息说退款成功，但售后、退款和渠道事实不一致，且会话已转人工。页面该依据什么显示？SSE 断开后应该结束任务还是恢复查询？

**B10B**：画一个精简退货系统，先不用 Agent。至少包含申请、寄回、收货三个动作，列出每个动作的身份条件、输入、校验、记录变化和完成判据，再说明加入 Agent 后哪一部分被替换、哪一部分必须保留。

## 自评与复练

每题分别检查四项：业务判断是否正确、依据是否明确、记录与后续责任是否完整、是否把局部能力误写为完整闭环。缺任何一项就回对应业务章补读。

能讲出结论但画不出记录变化，先回 B02；能算金额却不知道能否发钱，回 B03、B06；前端动作与后端事实混淆，回 B05、B10。综合重建先写自己的设计，再用 B10B 解析核对，不需要为了答题直接 build 项目。
