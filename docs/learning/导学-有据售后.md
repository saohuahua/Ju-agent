# 导学：有据售后 AfterSales Copilot

这套材料面向熟悉前端与 TypeScript、需要补齐后端与 Agent 工程基础的开发者。它的目标不是让你背下 22 章，而是让你读完主线后能回答四件事：

1. 一次客户退款请求具体经过哪些代码？
2. 为什么退款金额和资金执行权不能交给模型？
3. 渠道结果未知时，恢复为什么优先查询而不是重发？
4. 这个项目哪些能力有真实证据，边界又在哪里？

> **怎么用这份材料**：先走下面的"第一次学习路线"，**不必先读完 22 章**。完整目录、机制细节和扩展专题都放在路线之后，遇到问题再查。

## 第一次学习路线（5 个阶段）

阶段顺序来自真实的前置关系：不认识业务对象就读不懂事务；不理解事务和持久任务，就读不懂资金恢复；先弄清机制边界，再核对评测口径，才不会把"机制验证通过"误读成"模型质量好"。

## 项目技术亮点地图

这是面试和简历真正要讲的部分。每一条都写成**"解决什么真实问题 → 用什么机制 → 代码在哪 → 有什么证据 → 边界在哪"**，并标注它属于哪一类能力。

> **状态口径（务必区分）**：
> **当前默认入口** = 走项目正式离线入口（`pnpm dev:offline` / Compose，均设 `P6_BUSINESS_MODE=simulation`）时实际执行；
> **独立模块** = 代码与测试存在，但默认客户请求不走它；
> **历史实验** = 当时版本与条件下验证过，不代表当前版本；
> **待实现** = 只有设计与前提，没有落地。

| 亮点 | 解决的真实问题 | 采用的机制 | 源码与文档入口 | 现有证据 | 限制 |
| --- | --- | --- | --- | --- | --- |

每个亮点都能继续追问"为什么不采用更简单的方案"，这正是面试要考的地方。答案在对应章节里，不在导学里重复。先给出精简版，方便你对照记忆：

| 亮点 | 更简单的方案为什么不成立 | 采用机制后的代价 |
| --- | --- | --- |
| A 模型提意图、代码管业务与资金 | 让模型直接调用支付接口，金额与归属只能靠提示词和模型自觉；一次提示注入或一次幻觉就是资金差错 | 业务约束必须由代码显式实现并测试，规则变更有开发成本 |
| B 长任务与跨进程恢复 | 用一次长 HTTP 请求跑完，审批和寄回可能跨越数小时甚至进程重启，连接无法承载业务事实 | 增加状态表、关联记录与恢复代码；只覆盖命名故障窗口 |
| C 退款幂等与结果未知 | 超时就重试、失败就新建一笔，会在渠道已成功但响应丢失时重复退款 | `not_found` 不自动重发，部分情况需要人工核验，自动恢复率下降 |
| D 前后端状态一致性 | 把 SSE 当成状态源、用数组下标当游标、只比较运行 ID，会在过滤、重连和身份切换后错位 | 需要服务端投影、水位帧与前端版本号，前后端都要多写一层 |
| E 可追踪评测 | 只看一个总分或最终回复是否正确，无法解释失败在哪一层，也无法公平比较两个版本 | 每个用例要保存证据、哈希与条件元数据，维护成本更高 |
| F 检索与知识证据 | 直接把全文塞进 Prompt，语料变大就超预算；只靠模型解释又不保证出处可追溯 | 检索只辅助解释，资格仍由规则终判，检索收益需另做同条件对照 |

## 第一次遇到内部名词时

正文里的几个词容易混，先按职责记住，实现细节到对应章节再看：

- **run**：本次客户会话及其处理过程，不是登录会话。
- **task**：run 里的一段后台执行片段。一条客户消息可能经历多个模型 turn，一笔售后可能跨多个 task。
- **turn**：一次模型请求到一次完整响应。
- **worker**：定期取出待办并执行的后台代码，不是浏览器的 Web Worker。
- **checkpoint**：某个步骤已经确认的结果，恢复时据此复用。
- **lease / generation / fencing**：租约给执行者一段有限的处理资格；代次标识第几次接管；围栏写入要求"当前所有者与代次仍然匹配"才允许落库。
- **projection（投影）**：把内部记录转换成某个读者需要的视图，例如从多张业务表生成客户进度。

同名词要特别区分：**模型计量 token**、**人工审批一次性令牌**、**资金发送许可**三者的用途完全不同。

P6、P7、P8、P9、P10 是项目阶段编号，分别主要对应持久执行、模型预算、有限调查、评测治理和部署；它们不是需要先学会的五个框架。

## 证据口径

源码说明当前实现，实验说明特定版本与条件下验证过什么，计划说明预期。三条具体规则：

1. **离线测试与 L1 不作为真实模型效果**。L1 用脚本化模型驱动固定用例，检验的是宿主如何执行和治理动作。
2. **历史真实模型成绩不代表当前版本质量**。不同版本的数据集规模、Prompt 和环境都不相同。
3. **模拟渠道不等于真实支付**。本机模拟渠道能验证治理机制，不能证明真实渠道的幂等与查询契约。

本机真实模型传输可显式启用，[售后引导交接](../handoffs/customer-guidance.md)记录了有限真实接口与隔离业务链路复测，不代表总体模型成功率；本次文档补全未调用真实供应商。配置见[模型设置手册](../runbooks/model-settings.md)。个人贡献待本人核实，P10 容器仍待验收；P5 整体质量门槛不能凭传输接入认定通过。

引用数字前查[核心结论与证据索引](维护与证据/核心结论与证据索引.md)，准备简历前查[事实与贡献摘要](../interview/简历事实摘要.md)。完整写作标准保留在[写作约定](维护与证据/写作约定与章节规划.md)。
