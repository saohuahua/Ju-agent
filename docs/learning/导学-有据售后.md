# 导学：有据售后 AfterSales Copilot

这套材料面向熟悉前端与 TypeScript、需要补齐后端和 Agent 工程基础的开发者。学习重点是解释设计如何形成、模块怎样协作，以及哪些结果有项目证据支撑。最终目标是能够重建精简核心闭环，而不是记住技术名词。

## 阅读方式

优先采用下面的业务主路线，原 22 章保留为机制路线。每章先看阅读前提和实现思路，再看必要机制、故障案例、源码参考与证据。实现思路应足以帮助读者画出核心流程；源码用于核对真实细节，不要求先逐行读完整仓库。

前端常规语法不重复教学，后端基础随章节补齐。若某文件或原理看不懂，请结合具体路径继续追问 AI；导学提供阅读路线，正文解释实现思路，不逐行翻译整个仓库。22 章机制正文、10 篇业务详解与配套练习已按目录组织，源码、图示和链接的检查范围见[编写与复核记录](维护与证据/编写与复核记录.md)。

### 第一次遇到内部名词时

正文中的 run 是本次客户会话及其处理过程，不是登录会话；task 是其中一个后台执行片段；turn 是一次模型请求到完整响应。一条客户消息可能经历多个 turn，一笔售后也可能跨多个 task。P6、P7、P8、P9、P10 是项目阶段编号，分别主要对应持久执行、模型预算、有限调查、评测治理和部署；它们不是需要先学会的五个框架。

业务篇后半部的源码推演用于第二遍核对。第一遍先沿完整案例回答“谁输入、谁判断、保存什么、等谁继续”，遇到 holder、generation 等内部字段，按正文解释理解职责即可，不需要立即背 SQL。对于同名词，特别区分模型计量 token、审批一次性令牌和资金发送许可，三者用途不同。

## 证据口径

源码说明当前实现，实验说明特定版本与条件下验证过什么，计划说明预期。离线测试与 L1 不作为真实模型效果，历史真实模型成绩不代表当前版本。本机真实模型传输可显式启用，[售后引导交接](../handoffs/customer-guidance.md)记录了有限真实接口与隔离业务链路复测，不代表总体模型成功率；本次文档补全未调用真实供应商。配置见[模型设置手册](../runbooks/model-settings.md)。个人贡献待本人核实，P10 容器仍待验收；P5 整体质量门槛不能凭传输接入认定通过。

引用数字前查[核心结论与证据索引](维护与证据/核心结论与证据索引.md)，准备简历前查[事实与贡献摘要](../interview/简历事实摘要.md)。读完后应能讲清完整请求、事务受理、审批绑定、资金未知、租约抢占、SSE 补发、模型预算、有限分支及评测边界；这些是理解目标，不是对个人已掌握程度的自动认证。
