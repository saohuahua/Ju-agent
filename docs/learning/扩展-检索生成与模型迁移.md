# 扩展：检索、生成与模型迁移

本专题承接[第 12 章](12-政策检索引用与确定性判定.md)、[第 18 章](18-模型预算与费用账本.md)与[第 20 章](20-测试L1L2与Judge.md)。当前真实实现是可追溯政策快照、字符基线和独立 BM25 对照；向量检索、融合、重排、多版本在线发布、微调及真实多模型迁移属于扩展设计。

## 先定位缺口，再增加检索环节

客户说“键盘偶尔断连”，政策使用“质量故障”，词面可能没有足够重合；而订单编号、商品型号和精确条款名又很适合关键词匹配。Embedding 将文本转成向量，借助向量间相似度寻找语义邻近内容。它不是资格判断器，也可能把语义相似但版本、商品或客户范围不符的内容排在前面。

最小向量扩展需要保存片段身份、内容版本、模型版本及向量，并让查询使用兼容的编码方式。先按租户或可见范围过滤，再比较候选，避免用“先检索所有客户，再由模型删掉不该看的内容”作为隔离方案。模型升级后向量空间可能变化，需要重新构建或维持明确的版本边界，不能混用不兼容向量。

余弦相似度比较方向，点积同时受长度影响；向量归一化后两者排序可有对应关系，具体应服从编码模型与索引的契约。近似最近邻节省查询成本，但引入近似误差，不能把“数据库返回十条”称为召回完整。当前小语料也可以先做精确相似度基线，确认是否有质量收益再增加索引复杂度。

## 分块和候选容量怎样共同影响质量

当前 320 UTF-16 单位、无 overlap 的实现由短政策场景决定，不是普适最优值。长文可以按标题、条款或表格行等结构切分，过长部分再采用窗口。overlap 指相邻片段共享一段文本，可能保留跨边界上下文，也会增加重复召回与费用。

例如一条政策前半句说“七天内支持退货”，后半句列出不适用商品。如果恰好拆开且只召回前半句，模型可能生成错误结论。解决方式可以是父文档回读、相邻片段扩展或结构化保留完整条款，而不是无条件把所有 chunk 调大。表格拆分还应保留列名、单位与行条件，图片及扫描 PDF 则需要额外解析和证据定位，本项目没有这类实装。

评测应记录单片段长度、重复率、完整证据率、输入 token 与答案支持情况。一次调整 chunk size 同时改变片段数和检索对象，不能仍称其为相同索引。当前 P4 的 19 篇短文得到 19 个片段，数据无法证明复杂长文边界的效果。

## 混合候选与倒数排名融合

两个检索器的原始分数可能量纲不同，直接相加没有明确依据。倒数排名融合 RRF 使用候选在各结果列表中的名次：对文档 d，将各列表中 `1 / (c + rank(d))` 相加，未出现则该列表贡献为零，名次从 1 开始。常数 c 控制头部名次差异的影响；这里 c 不等于最终返回数量 Top-k。[官方 RRF 公式说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

下面是教学算例，常数取 60，仅用于算清融合行为，不是项目实验或推荐参数。

| 文档 | 词项名次 | 语义名次 | 融合值 |
| --- | ---: | ---: | ---: |
| A | 1 | 未进入候选 | 1/61 ≈ 0.01639 |
| B | 2 | 1 | 1/62 + 1/61 ≈ 0.03252 |
| C | 未进入候选 | 2 | 1/62 ≈ 0.01613 |

B 因两路都靠前而排到前面。应用前要先统一文档或片段身份，决定按什么粒度去重；同一原文不同版本不能无条件合并。候选窗口太小会在融合前丢掉依据，两路都没召回的文档也不可能靠融合恢复。

重排与融合职责不同。融合合并不同排序结果，重排进一步判断查询与候选相关性，但通常不能找回候选池之外的材料。若加入重排，应分别保存召回候选、融合结果、重排结果及最终送给生成器的内容，从而判断是哪个阶段丢失依据。

## Top-k 与评测指标

Hit@k 关注前 k 中是否至少有一条相关证据；Recall@k 关注标注相关集合被覆盖了多少；MRR@k 关注第一条相关结果的位置；完整证据率要求该题所需证据全部出现。它们解决的问题不同，多条件退款题不能仅用“命中一篇”的指标代表答案可成立。

例如需要 A、B、C 三篇政策，返回 A 和两篇干扰，Hit 可以通过，Recall 只有三分之一，完整证据为失败。如果 k 小于必要证据数，完整证据率存在容量上限。反过来，扩大 k 可能提升覆盖却增加无关内容、成本和生成干扰。

当前项目的文档级宏平均以每题为单位平均，不能混成按文档数量加权的微平均。无答案题单列，不应给它伪造一个相关集合再计算 Recall。用于调参的保留集已经不再真正未见，需要新样本支持下一轮独立结论。

## 召回到生成的归因实验

一次完整归因要保存题目、标注依据、实际候选、传入上下文、回答与逐条引用。可以依次做以下设计，不必同时更换全部组件：

1. **固定生成，替换检索。** 检查新的候选是否补齐原先遗漏；回答改善也要看输入 token 是否改变。
2. **给出标准证据。** 如果答案仍错，说明只改善召回不够，应检查生成和任务解释。
3. **固定证据，只改 Prompt。** 用明确假设测试是否减少遗漏条件、错误引用或无依据承诺。
4. **独立核验业务决定。** 对照订单、时钟与领域规则，不让自然语言回答成为资格金标准。

这些是建议实验，没有在当前真实模型上运行。没有标准证据或人工标注时，应说明缺口；不能拿“引用字段非空”代替答案支持率。对于没有足够证据的问题，正确补问或升级可能比流畅回答更符合成功标准。

## 知识更新与多版本发布

当前冻结快照不匹配就拒绝，优点是不会静默混用，代价是缺少新旧版本在线共存。若需要不停机更新，候选流程是：构建新版本 → 校验内容与引用 → 跑固定回归 → 发布新版本指针 → 新运行采用新版本 → 旧运行保留旧引用。

每个版本保存原文、分块配置、索引配置和内容哈希。构建失败不覆盖当前版本，回退只改变新请求的默认选择，不随意修改已有运行的授权事实。旧版本何时清理要考虑在途运行、审计和数据删除要求，不能因为索引文件占空间就让历史引用失效。

若政策变化影响尚未执行的业务，要由业务规则定义重新审批或终止条件；技术上能读取旧版本，不代表法规或业务上永远允许按旧规则执行。这一策略需要产品规则，项目当前没有实现通用发布与回退系统。

## RAG、Prompt 与训练的不同落点

RAG 提供外部证据，Prompt 规定如何理解任务与使用证据，训练改变模型参数所体现的行为。经常更新并需要来源的政策，适合先从知识版本和检索改进；稳定格式和任务行为可以讨论训练，但需要可靠训练数据、独立评测与成本方案。

三个方向都不能代替权限校验、幂等和渠道核验。模型学会输出正确格式不代表资源归属正确；检索到真实条款不代表满足退款条件。当前不做微调的理由是尚有可明确定位的工程和验证工作，且没有完成足以支持训练收益的当前真实模型基线，而不是断言训练永远没有价值。

## 模型迁移先过协议，再比较行为

API 形状相似只解决部分调用方式。适配器至少要处理文本、工具调用身份、增量参数、停止原因、错误与 usage，并核验能力声明。流式参数可能跨片段形成完整 JSON，不能把中间片段当作最终参数；重复调用 ID 或缺失完成标记也不能静默接受。

候选迁移流程是先冻结新配置和价格来源，运行协议契约样本，再在相同题集和政策条件下比较业务质量。协议通过回答“能否正确交流”，效果回归回答“完成任务是否更好”，两者缺一不可。旧运行继续用原配置快照，新运行才能选新模型，避免恢复过程悄悄换行为。

真实未知价格应拒绝进入受控计费路径，不能按零费用占用预算。超时后的备用模型也不是免费重试：旧调用费用风险继续保留，新的尝试重新预算，且不得重建已进入资金阶段的业务。当前 P7 仅支持显式 simulation，配置中的能力字段与人工线协议测试不是供应商验证。本任务没有解锁真实传输。

| --- | --- | --- |
| 工具和流协议是否兼容 | 正常、坏流、取消、停止与 usage 契约 | [P7 模块实验](../experiments/p7-model-gateway-v1.md)，仅人工协议事件 |
| 同任务效果是否变化 | 相同条件逐例结果和失败归因 | [P9 比较机制](../experiments/p9-fixes.md)，不含当前真实模型成绩 |

| 替换后资金是否重复 | 原业务键和渠道计数 | [P6 客户退款实验](../experiments/p6-conversation-refund.md)，模拟渠道 |

本专题的下一步应由实际失败触发。若主要问题仍是权限或未知资金，增加检索模型不能解决；若主要问题是语义遗漏，先做单变量检索对照，再决定是否值得增加成本。
