## 第一部分复核

复核入口包括 `main.ts`、`model-entry.ts`、`composeSystem`、创建及继续路由、客户工作台请求、会话与业务 Worker、客户事件白名单和退款进度投影。新章节链接逐项检查存在。

发现并处理的重点：

- 旧架构文档以 AgentRunner 与 WorkflowEngine 为主，新教材明确默认持久路径为 DurableConversation 与 DurableBusiness，不混用两套控制流。
- 创建持久请求返回 202，旧分支返回 201；正文区分受理、业务完成和客户获知。
- 当前 main 可在同一进程内嵌模拟渠道，但仍使用独立数据库；教材不笼统声称每种部署的渠道都运行在独立进程。
- 图中数据库到客户的虚线注明由 API 读取事件后推送，避免误解为数据库主动推送。
- 客户进度成功需要联合核验业务、资金效果与执行权，正文不使用模型文案判断资金成功。

本部分未运行业务测试或 build。以上是源码与文档检查，不新增测试通过数。已用独立无头 Chrome 渲染 SVG 并检查视口溢出，首次预览发现时序图标签被节点遮挡、状态图标签与连线接近，已调整；浏览器渲染与 Typora 实际显示分别记录。

## 第二部分复核

核对请求与身份代码、ConversationJournal、P6 建表与仓储、执行权迁移、领域状态表及对应测试。

- 修正关系图中退款基数，`refunds.return_no` 为唯一字段，同一售后至多一条退款记录。
- 区分任务状态与会话状态，`reconcile` 是操作，不是新状态；任务完成不等于资金完成。
- 区分同一文件与同一连接，明确仓储事务回调不能跨网络等待。
- 明确 SQLite 支持独立连接竞争，但不据此宣称多节点水平扩展；锁等待不代替业务防重。
- 按用户要求改用七种内容对应的 SVG 结构，节点文字居中，并保存可维护的图形定义与生成脚本。

## 第三部分复核

逐项比较旧 AgentRunner 与当前 DurableConversation，检查模型协议、上下文重建、工具目录、只读工具与知识快照。

- 旧 Runner 的查单后动态门控未被当前持久会话直接复用，当前是冻结工具版本控制集合；已在第 08、11 章区分。
- `buildManagedContext` 的工作便签及旧工具结果清理是模块事实，持久会话目前只调用 `rebuildMessages`；旧组合根也未显式提供 tokenBudget。第 10 章不声称默认压缩已启用。
- 当前持久会话确认完整模型轮次，不持久化未完成增量；第 09 章区别旧路径逐片段事件。
- BM25 为已有实验与知识页对照，当前持久检索是字符基线 Top3；未将向量、融合、模型重排或多版本发布写成已实现。
- P4 指标使用实际排除规则与分母，不将引用定位正确当成答案忠实或退款资格正确。

本部分未调用模型、未重跑业务测试。章节链接全部存在；图示采用独立 SVG，并按语义分别设计职责双链、协议循环、上下文分层、安全边界及检索判定双链。

## 第四至第六部分复核

重新读取或定位了持久会话、任务认领与围栏、资金 Worker、P7 账本、P8 调查、政策检索、指标聚合和服务端 SSE 的关键分支，并对照章节引用的实验。重点检查：

- 批准、授权受理与首次发送分别确认；退货等待期不会因为批准就发送资金。
- 已有资金意图时走原交易核验，not_found 不能推出可以重新发送。
- 旧代次不仅不能写成功，也不能覆盖新执行者的失败和释放状态。
- 业务结果确认与客户投影分开，重连只恢复展示，不能触发重新退款。
- unknown 和 held 保留费用风险，active 不等于本地协程数，P8 记忆保留原未知业务。
- P9 业务成功和 Judge 分开；部分兼容比例零分母返回 1，正文新增实际分母与无证据解释。
- 模拟器与业务数据库独立不等于所有演示均为独立渠道进程；Windows 进程恢复不代替 Docker 验收。

正文补充了请求丢响应、两连接竞争、退货多次交接、消息配对、迟到结果和双库恢复等推演。新增内容描述实际机制或明确标记的教学场景，不虚构开发历史、线上事故与个人贡献。
