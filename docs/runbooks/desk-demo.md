# 正式工作台离线验收

本入口使用真实 API 事件与数据库 配套脚本模型和构造业务数据 不调用外部模型

在仓库根目录分别启动两个终端

```powershell
pnpm --filter @aftersales/api demo:desk
pnpm --filter web exec next dev --turbopack -p 8790 --hostname 127.0.0.1
```

打开 http://127.0.0.1:8790/console

API 仅监听 127.0.0.1:8787 数据保存在独立的 data/desk-demo.db 不读取 .env 或模型密钥

首次启动创建机械键盘售后样例 并通过真实运行器查询订单 搜索政策和升级人工 会话标为评测

重复启动会保留已有案件 备注与人工回复 不自动重置数据 新模型会话入口保持禁用

验收顺序

1. 选择案件 检查客户消息 工具轨迹 订单与政策候选
2. 保存内部备注 打开内部备注页签确认内容
3. 接管案件 切到回复客户 输入回复 确认会话流和队列预览更新
4. 打开政策原文 使用关闭按钮或 Escape 退出 确认焦点回到原按钮
5. 切换到客户李娜 确认团队案件详情立即消失
6. 切回专员 验证关键词搜索和空结果
7. 检查知识与政策及运行设置导航

政策关键词基线可能召回不适用条款 这是待改进检索能力的真实坏例 不要将引用展示视为政策适用判定

人工结案已核验案件关联的退款 补偿 价保及审批执行状态 未完成或结果未知时阻止提交

提交会在事务中重新核验并同时保存状态 客户事件与审计 结案本身不会执行资金操作

独立内存验收可运行 pnpm --filter @aftersales/api exec tsx test/fixtures/closure-ui-server.ts
该入口占用 8787 端口 不要与离线演示 API 同时启动 测试记录随进程退出丢弃

浏览器验收不会证明模型能力 进程恢复 并发审批或预算限制

分页专项可将 API 启动命令改为下面的命令 同一端口不要同时启动两个 API

```powershell
pnpm --filter @aftersales/api demo:desk --pagination
```

此模式使用独立的 data/desk-pagination-demo.db 首次建立 36 条模拟案件 其中 35 条明确标记为界面验收夹具

检查首批 30 条 点击加载更多后为 36 条 搜索可跨分页查找 已完成记录显示记录已同步

完成专项后停止该进程 重新使用不带参数的 demo:desk 即可回到原演示库 原备注和回复不会被分页数据覆盖
