## 发现与修复

1. 首次进程证据写入被沙箱 EPERM 拒绝，工具权限审查获准后复跑。格式化遇到同类写权限限制亦记录并获准重跑。
2. 新 HTTP 夹具首次缺少 decidedBy 字段导致 400，补齐契约必填项。首次观察到夹具其他售后单状态，改为精确查询 RT1，未改业务断言。
3. 新测试清理回调返回 Database，与 void 声明冲突，改为显式无返回清理。
4. 首轮全仓 P6/P7 检查点场景没有触达强退点。只读证据为 running、attempt 1、无步骤无事件，夹具租约只有 30 毫秒。改为 1 秒，并让恢复进程等真实租约到期，不依赖启动耗时。
5. 正式 L1 初次回放暴露弱模型脚本与动态目录的不同测试目标。仅 L1 离线回放显式提供完整动作目录，保留领域越权测试；未放宽 L2 或 P7 协议。
6. P7 校验发现无检查点恢复的动作调用悬空。恢复时为原调用追加明确中断错误结果，不伪造成功或直接重发资金。
7. 审批期间物流通知先于实际动作结果出现在模型上下文，造成工具配对不合法。重建时先交付真实结果再交付挂起通知，原审计顺序不改，且不为未来工具调用生成虚假配对。
