# 简历事实摘要

整理日期：2026-09-28。目标岗位为 Agent 应用／全栈研发。本文为简历与面试提供事实底稿，**当前不生成未经确认的个人业绩表述**。

## 项目定位与已实现能力

有据售后围绕售后业务建立自然语言交互与确定性执行的协作边界。默认入口在本机 simulation 下支持两类持久退款，具备申请、审批、寄回、收货、资金确认与客户展示链路。技术栈包括 TypeScript、Hono、Next.js／React、Zod、SQLite 和 Vitest，实际依赖见各包声明及锁文件。

可用于项目简介的客观表述：

> 面向售后长流程的 Agent 工程项目，将模型工具调用与确定性业务授权分离，通过持久任务、退款执行权、预算账本及事件投影实现本地离线可复现的两类退款闭环，并保存可追溯评测与故障恢复证据。

| 工程支柱 | 可核验技术动作 | 可支持的结果 |
| --- | --- | --- |
| 业务执行治理 | 领域重查、审批绑定、业务键、执行权、发送意图 | 模型意图不能直接成为资金执行授权 |
| 持久恢复 | 命令与任务同库受理、租约代次、检查点、查询恢复 | 命名退出窗口可保留原关联并继续处理 |
| 知识证据 | 快照、来源偏移、字符与 BM25 对照、独立领域终判 | 政策出处可定位，检索与业务判断可分别分析 |
| 费用治理 | 统一网关、共享预算、逐尝试预占、未知保留 | 并发和重试有持久计费约束，恢复不清零风险 |
| 前后端一致性 | 客户白名单、SSE 游标、订阅隔离、请求键 | 断线补发与身份切换有明确协议和对应测试 |
| 质量证据 | L1／L2、逐例结果、元数据、失败分类、报告核验 | 能区分业务、服务、协议及 Judge 问题 |

完整口述素材见[面经](面经-有据售后.md)。这里的支柱是项目事实，不自动成为个人负责范围。

## 可量化结果及条件

- 2026-09-26 P10 修复记录中，全仓测试 692/692，正式 HTTP 离线 L1 另计 124/124；来源为[修复交接](../handoffs/p10-source-manifest-fix.md)，不是本轮重测，也不是模型准确率。
- 2026-09-25 P4 固定小题集里，BM25 的 holdout Recall@3 为 0.86，字符基线为 0.76；相关题分母 10，同时 Recall@5 从 1.00 降至 0.95。来源为[P4 报告](../experiments/rag-baseline-v1.md)，不能写成“检索全面提升”或线上收益。
- 2026-09-27 P11 专用夹具中，两筆成功模拟退款各提交一次、成功动作一次；另一笔保留 unknown，提交一次、成功动作零次。重启和双库恢复后状态与计数保持，见[演示摘要](../experiments/p11-learning-evidence/demo-summary.json)。该结果不能推导 unknown 在真实渠道中必定未发生。

其余数字及限制统一见[核心证据索引](../learning/维护与证据/核心结论与证据索引.md)，避免在多份简历素材中产生不同分母。

## 已验证机制与尚未验证内容

已有代码与历史实验支持的机制包括角色归属、请求重放、审批原子性、等待期零资金、旧代次拒绝、指定故障恢复、客户事件投影和未知费用保留。它们均有范围：模拟协议、独立演示数据、本机进程和指定故障点。

尚不能作为成果使用的内容包括：真实支付集成、当前真实模型质量、真实 Judge 校准、生产上线、实际客户量和降本比例、通用 DAG 编排、跨会话长期客户记忆、MCP／业务 Skill 产品接入及 P10 容器运行通过。不能因面试官问了这些问题就补成已做经验。
