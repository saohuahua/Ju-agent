# ADR-004 / ADR-011 追问稿 为什么不用 Mastra 为什么不用 MCP

本稿只覆盖「为什么不用现成框架」这一条追问链 其余高频追问见 STAR.md
每条回答都能指到仓库文件 拒绝无法验证的说法

## 主问题 为什么自研 Agent 循环 不用 Mastra

面试官问法变化 你为什么不用现成框架 这不就是重复造轮子吗 现在主流都上 Mastra

40 秒标准回答

- 先定位核心资产 这个项目的价值在评测闭环与副作用治理 不在 Agent 循环本身
  循环只是胶水 模型接口层加脚本化实现共三百余行
- 调研文档本身推荐 Mastra 但强调「首版保持克制」 决策留痕在 ADR-004
- 自研循环换来三个必须完全掌控的点
  结构化输出校验与修复 轨迹事件化 ScriptedModel 离线确定性
  框架的抽象层恰好会遮住这三个点 校验修复轮在框架里不可见
  逐 token 事件落库要打洞 离线脚本模型在框架内做对称实现几乎不可能
- 收口 自研的边界很窄 不是自研框架 是自研一个可控的循环

证据锚点

- ChatModel 接口 五种结构化输出形状 packages/agent/src/model.ts
- 双实现 脚本化与真实模型对称 packages/agent/src/scripted-model.ts packages/agent/src/anthropic-model.ts
- 决策记录 docs/adr/DECISIONS.md ADR-004

## 逐条追问

### Q1 Mastra 也有 workflow 编排 你为什么连工作流都自己写

防守 我需要的工作流语义是 逐步存档 断点恢复 租约互斥 一次性审批令牌 幂等键
且与领域层强耦合 packages/workflow/src/engine.ts
框架 workflow 与这套语义是两套东西 移植等于重写
断点恢复是核心卖点 进程中断后从事件重建续跑 这是评测用例常态验证的行为
框架里做这个要反向理解它的执行模型 成本高于自研

### Q2 说白了你就是不会用 Mastra 吧

防守 不辩解 直接展示对框架的了解 Mastra 提供 workflow 图编排 agent 记忆
MCP 客户端 我要的三件事它都不以我想要的方式暴露
决策不是能力问题 是约束问题 无 Docker 所以 SQLite 优先 ADR-002
零外部依赖所以租约表代替 Redis ADR-003 评测对称所以自研循环 ADR-004
这是一套连贯的环境约束推演 不是逃避学习
且迁移点已预留 ChatModel 接口 真要上框架 一周内写一个适配器

### Q3 为什么不接 MCP 现在大家都在用 MCP 接工具

防守 先承认 MCP 的价值 跨进程工具接入与生态共享 我的场景用不上
本项目的工具全部是仓库内 TypeScript 函数 契约在 contracts 包用 Zod 定义
进程内直调零开销 ADR-011
引入 MCP 的代价是实的 独立进程与 stdio/SSE 传输增加运维面
JSON-RPC 包装与内部契约之间多一层转换
轨迹事件化要求每个工具调用逐 token 落事件表 跨进程边界使这一步多一层序列化
离线确定性要求 ScriptedModel 对称 MCP 工具还要额外做脚本化适配
更关键的是安全 外部 server 是新增信任边界
我的纵深防御靠白名单即最终权限边界 接 MCP 等于把这个边界交给第三方进程
将来接外部工具生态时 MCP 是候选 接口已预留 决策留痕 ADR-011

### Q4 自研这么多 求职市场上不如会主流框架的人

防守 面试讲「循环每一步为什么这么写」比「框架帮我们做了」更有区分度
十一条 ADR 的决策链就是框架源码级的思考过程
招聘方要的是能解释权衡的工程师 不是会调 API 的
而且主流框架的 API 我都看过 迁移成本可控 这回答本身就是在展示学习能力

### Q5 自研的东西 团队接手成本高

防守 循环三百余行 十一条 ADR 决策留痕 单元测试覆盖
真实团队场景我会评估框架 个人项目的约束与目标不同 答案本来就该不同
这个回答要诚实 不是「自研一定好」 是「在这个约束与目标下自研是对的」

## 口径红线

- 不贬低 Mastra MCP LangChain 承认价值与适用场景 只说约束不匹配
- 不说自己「更懂」 说「约束不同」 决策推演链比结论更有说服力
- 不夸大自研规模 模型接口层与脚本化实现共三百余行 是循环不是框架
- 被追问细节时主动报 ADR 编号 决策留痕本身就是工程习惯的证据
