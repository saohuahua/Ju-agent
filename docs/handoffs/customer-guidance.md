# 半自动售后引导交接

日期：2026-09-28。本次在现有持久会话、客户页面和坐席工作台上增加售后咨询引导，没有新增聊天表、通用规则引擎或坐席分配系统。

## 当前行为

- 新建持久会话使用 `customer-guidance-v1`，旧会话继续使用冻结快照，不自动扩权或切换提示词。
- 完整匹配的问候、服务范围、退货步骤与人工入口询问使用固定答复，不调用模型；复合诉求和待补问答案不会被这些规则截断。固定答复也写入事件和模型上下文。
- 普通咨询允许连续追问，`conclude` 在新版表示本轮答复完成，补齐工具结果后进入 `awaiting_input`；用户显式结束咨询才进入完成态。退款完成和人工结案保留原终态。
- 政策解释先检索，咨询不代表授权办理。新版沿用字符检索基线，返回条数从三条增至五条；未启用 BM25 或新的检索基础设施。
- 意图连续两轮补问仍未明确时展示业务选项和人工入口。补问只展示 `ask_user.question`，避免同轮模型正文重复索取信息。
- 人工申请不依赖模型。空闲普通咨询原会话转接；有运行中任务、退款关联、失败或已结案时创建关联人工咨询。来源记录可从客户页面和坐席工作台查看。
- 客户明确发送“请转人工”等完整指令与按钮复用受理路径；否定转接和询问入口不直接转接。
- 本轮没有新增换货、补偿、价保办理能力，不改变退款执行权、审批和资金未知状态。

## 接口与兼容

- `POST /api/human-help`：客户身份，要求 `Idempotency-Key`，可选 `sourceRunId`，返回 `202 { runId, accepted: true }`。重复请求复用原受理结果，同键异参冲突；已有相关待人工或人工处理中咨询时复用该记录。
- `POST /api/runs/:runId/messages`：新增可选 `action: end_consultation`，仍提交 `message` 和请求键。仅新版普通空闲咨询允许结束，退款关联、活动任务和人工案件不能借此结束。明确转接文本可能返回新的关联咨询编号，客户页面据此切换。
- `run.paused` 新增可选 `consultation: ready | clarify` 和 `showChoices`；新增 `human.requested` 事件承载来源会话。事件序号与刷新恢复规则保持不变。
- 控制命令复用 P6 请求键和事务，同一事务完成控制任务、状态变更及事件写入，不进入模型或资金 Worker。
- 真实模型已启用但浏览器缺少管理口令时，请求明确失败，不再因缺少口令而静默创建模拟会话。
