# 客户消息与处理进度修复

日期：2026-09-28。目标是恢复默认持久客户对话的用户消息、助手回复、订单候选和等待补充状态，并展示可以从系统事件核实的处理动作。DeepSeek 官方请求仍关闭 thinking，不展示或回传原始推理。

## 根因与修复证据

故障历史会话 `run_19ce2d30-3e50-4987-8023-a618caa5f34e` 的后台和 JSON 接口已有用户消息、订单候选、回复及暂停事件。普通 curl 未请求压缩，因此能直接读取 SSE；浏览器请求包含 Accept-Encoding，经 8790 的 Next 代理后返回 gzip，却只收到 10 字节压缩头，业务事件被压缩缓冲。独立 Chrome 复现连接打开但收到零条命名事件、消息区空白，没有 JavaScript 异常。

两个现有 SSE 响应统一增加 `Cache-Control: no-cache, no-transform`，禁止代理转换流。相同浏览器回放随后收到原五类事件，用户消息和助手回复恢复；订单卡片原本要求 `missingSlot`，真实模型暂停时该字段可缺省，因此改为在等待补充且实际收到候选时显示。新回合恢复会清除上轮候选，避免重新显示过期选单。

## 消息与进度链路

客户历史列表只展示售后咨询 状态和发起时间 不展示内部 runId 健康连接时不重复显示连接诊断 断线仍提示恢复状态 商品选择消息仅把后台 itemId 转为已有候选订单中的商品名 订单号仍可用于核对 原始命令和内部关联字段保持不变 售后单号与物流单号仍用于业务查询

- 默认持久会话的 `message.user` 新增可选 `requestKey`，与受理事务使用同一幂等键。旧事件保持兼容，不按文本推断确认。
- 智能会话提交前显示本地消息，HTTP 成功显示已受理，公开事件按键确认后使用后台脱敏文本。相同文本的不同请求分别保留，重试同键不新增本地条目。
- 30 秒未确认 HTTP 结果时保留草稿和原请求键。5xx 或网络失败标记结果未知，明确 4xx 标记发送失败。事件已确认后 HTTP 失败不再误报未知。人工会话留言继续使用原有服务与事件展示。
- 身份变更卸载客户会话，选择变更推进本地代次，旧请求和取消订阅后的回调不得改写当前视图。原 SSE 的运行归属和单调序号过滤继续生效，公开序号允许跳跃。
- 持久查询在开始时写 `tool.requested`，确认结果时写 `tool.completed`，两者共享运行内稳定标识。开始检查点不替代原工具结果，租约围栏继续约束写入。
- 客户 JSON 与 SSE 共用白名单投影，仅公开最近订单、订单核验、物流查询、政策检索的动作名、执行标识及结果状态，不公开参数、结果、内部错误或模型原始内容。
- 会话标题和状态栏展示当前动作、等待选择或处理失败。新用户回合清除当前动作，保留历史工具列表。实时连接状态与业务处理状态独立显示，不生成百分比。
